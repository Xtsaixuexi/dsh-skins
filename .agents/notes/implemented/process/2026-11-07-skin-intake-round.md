# Agent Note: 2026-11-07 皮肤收录轮

Status: implemented

## Problem

2026-11-07 的皮肤收录轮需要对仓库当前开放的 6 个 PR（#77、#85、#93、#97、#99、#104）按版本递增规则、改动边界、必需检查状态与用户可见截图证据逐项复核，裁定已合并皮肤的后续修复 PR #104 是否满足上架更新条件并可合入 `main`，同时核验返修 PR #77 的会话态截图是否足以证成「背景模糊滑杆已归零」与局部 scrim 边界，以及确认其余开放 PR 的阻塞或待更新状态。

## Decision

- **#104（`equation-sea` 可读性修复）：合并（`367e0a8be`）。** 这是 2026-11-05 已合并皮肤 `equation-sea` 的后续修复。核验：`skin.json` 版本由 `1.0.0` 升到 `1.1.0`（不升版商店不会当成更新）；改动 9 个文件全部落在 `skins/equation-sea/` 与 `evidence/` 内，未触碰皮肤中心代码；三项必需检查通过、`mergeable` 为 `CLEAN`。上一轮遗留的「预览图内文字仍写旧对比度数字」问题一并修正，图内现为 `≥4.5:1`、与 `README` 新表一致；`evidence` 与 `preview` 逐字节一致。
- **#77（`whale-watercolour`）：再次退回。** 桌宠浮窗与封面混入会话态都已修好（`preview`、`evidence`、`home` 三份文件 `sha256` 一致，封面为干净首页态），来源声明齐全；但会话态截图里两侧画面列整片是无细节的蓝白雾，而同一视口同一皮肤的首页图里发丝、花瓣、云边都清晰，因此「背景模糊滑杆已归零」在图上读不出来，局部 scrim 边界也不可见。要求重拍会话态使两侧列露出清晰画面与纱边界，或补一张滑杆为 `0` 的设置截图作为凭证；另请核对 `README` 第 136 行记录的 `sha`。
- **#85、#93、#97、#99**：维持既有状态，#85 仍阻塞（零截图证据、分支冲突、为接入未发 npm 的插件越界改动皮肤中心委托皮肤契约），#93/#97/#99 的作者未更新。

## Alternatives considered

- **采信 #77 作者关于「背景模糊滑杆已归零」的文字说明并直接放行合并。** 否决：在同一视口与同一套皮肤资源下，首页态截图两侧画面列的发丝、花瓣与云边细节清晰可辨，而会话态截图同位置整片呈现无细节的蓝白雾化效果，两张截图同屏比对即构成直接反证；口头或文字说明无法替代画面上可核对的视觉证据。
- **将 #104 视为已收录皮肤的纯样式微调，豁免 `skin.json` 版本号递增核验直接合并。** 否决：商店分发链路依赖 `skin.json` 的版本号比对识别可用更新，若版本号维持不变，客户端不会将改动后的资产包识别为新版本下发，已安装旧版的用户将无法收到本次可读性修复；经核对 `skin.json` 已由 `1.0.0` 递增至 `1.1.0`。

## Consequences

- 合并后 `dsh-skins` 的 `main` 推进到 `367e0a8be`，本轮已同步在 `dsh-web` 移动 `satellites/dsh-skins` 的 gitlink 并重建 `market/dist`（65 skins）。
- #77 的会话态截图问题属「证据不可核对」，不是素材质量问题：素材 `bk-bg.webp` 本身通过，问题在于证明不了背景模糊已关；下一轮只需补一张能读出来的图。

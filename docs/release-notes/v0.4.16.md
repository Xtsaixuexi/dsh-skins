皮肤中心发布 0.4.16，沿用 dsh-web 家族的统一版本号。本版本皮肤目录从 62 套增至 65 套：新增 md3、pixel-whale、equation-sea 三套，DIY Journal 的包体量压掉约 62%。皮肤中心把全屏面板与设置对话框改为不透明绘制，并让全屏面板只在展开时绘制；equation-sea 修过一轮可读性；四套共用发送键规则模板的皮肤不再把附件栏算进去；model-dorm 补上浮动层令牌。npm 白名单仍只内置 `blue-fantasy`，包名、安装方式与语义属性名一个不动。

> **兼容性**：本版本没有破坏性变更，也没有需要手工迁移的改动：包名 `@linxin666/dsh-client-ui-skin-center`；安装方式（`dsh plugin --profile <name> add` 与 `$DSH_HOME/skins/<id>` 目录布局）；npm `files` 白名单仍只内置 `blue-fantasy`，三套新皮肤是市场内容、按需装进 `$DSH_HOME/skins/<id>/`；`dsh.engines.dsh` 与 `@deepseek-ai/dsh` 对等依赖下限仍是 `>=0.2.2-rc.1`；v2 活跃状态文档的持久化文件名与键名；`data-dsh-skin`、`data-dsh-part` 等语义属性名；线协议字段——全部未改名。皮肤中心新增的两条不透明绘制规则写在共享样式表里，皮肤不必声明新令牌。Reviewed Skin Hooks 记录里只有 diy-journal 一条的 `manifestSha256` 随它改过的 manifest 更新，其余 26 条与全部 `hooksSha256` 不动。

### 新功能

- 新增 `md3` 皮肤（abaa29d，#80）：把 Material Design 3 官方 Baseline 紫调配色整套搬进 dsh，亮暗两套都是官方 Baseline 调色板，primary / secondary / tertiary / error 各自带 container 与 on-* 前景，surface 走五级容器，高程用色调分层而不是投影，形状按 4 / 8 / 12 / 16 / 28 的 MD3 尺度，hover 与按下用 8% / 12% 的前景状态层；底板为亮暗各一段 20 秒无缝循环的线框几何漂浮视频（`assets/float-light.mp4`、`float-dark.mp4`），可退回静态首帧。同一 PR 里的 `md3-blue` 被评审判为 md3 的简单换色而拒收，因此只发布紫调一套。落地过程逐条修掉评审项：面板、卡片与设置面板改到 MD3 surface 的不透明档（`bg-layer-1..4`、`bg-overlay`、`specific-input-major` 取官方 surface 色，只留 `bg-base` 与侧边栏半透明）；输入卡改成在 `[data-composer-dock]` 内把 canvas 令牌换实色，不再额外盖一层实色（那一层会压住输入卡底边），底板保留可见；内联图标改 `vertical-align: middle`，下拉箭头不再比文字低一两像素；去掉发送键的形变；禁用态按钮与暗色 error 色提亮一档；补上 `LICENSE`、六张真实宿主截图与中英 README，皮肤版本 1.3.1
- 新增 `pixel-whale` 皮肤（1841d5f，#84）：俯视的像素海面，256×144 画布逐像素算出十二阶海水、破峰亮线与碎浪后按最近邻放大，鲸鱼娘是四十像素长、十色、带深色描边的像素形象，在水面仰泳并沿 S 形路线来回游；侧边栏铺两张 160×220 透明 GIF 雨幕。这是一套单外观暗色皮肤：`contributes.backgroundMedia` 的两档都指向同一张 `assets/sea.gif` 与同一套 scrim，96 条官方别名令牌全钉在深海配色上，所以亮色模式的宿主也渲染夜海，两档不会漂移。评审项逐条落地：菜单面从 `#f8f9fa94` 加 40px blur 改成 `#0a1826f5` 并关掉背景滤镜（亮色主题给的菜单面在皮肤文字下只有 1.59:1）；11 条写成 `--dsw-alias-specific-*` 的令牌改回宿主真正消费的 `--dsw-specific-*`（别名写法在官方主题里出现 0 次），`--dsw-alias-shadow-lv[1-3]` 改回 `--dsw-shadow-lv[1-3]`；补上从未重映射的菜单图标、分组头、链接、`label-shimmer`、`label-deep-diving[-shimmer]`、`state-idle-primary`、`switch-thumb`、文档预览与选中、代码 diff 与文件 diff；交付、变更、计划、日程四类卡片改按 `data-presented-file`、`data-changed-files`、`data-plan-card`、`data-tool="schedule_create"` 锚定（旧的 `.kuvljq_*` 镜像随 CSS Modules 重建失效）。WCAG 合成背景量测：菜单 1.59 → 14.17、菜单分组头 2.77 → 5.50、侧边栏 1.18 → 10.51、输入卡 1.23 → 12.60、气泡 1.11 → 7.13、文件卡 1.18 → 12.53。证据换成一张 2048×1152 的真壳截图（亮暗各一，会话里有一条真实回复），预览由同一批截图重出；`NOTICE` 写清 AI 生成的来源、角色归属与贡献者责任句，README 补一节 Size 记原始字节数（`sea.gif` 5,711,209 字节，即 5.45 MiB），皮肤版本 2.1.1
- 新增 `equation-sea` 皮肤（548ae99，#101）：透明皮肤，暗色是黑洞吸积盘原片、亮色是同一张图洗成的羊皮卷手稿，面板是磨砂玻璃，厚度随「背景遮挡」滑块在 0–100% 连续变化，所有 alpha 都写成 `calc(base + var(--dsw-skin-scrim) × delta)`，所以皮肤中心的滑块在皮肤之上继续生效；代码块强制不透明，星野不渗进语法高亮。评审项落地：主操作前景色换成高对比值（亮色 `#ffffff` on `#9c3b2a` 6.83:1、暗色 `#06080c` on `#8fb6ff` 9.83:1，过 3:1 的主操作令牌契约）；亮色的 hover、dimmed 与 info-hover 从蓝色系挪进朱砂系；删掉无人引用的 `assets/backdrop-light.jpg`；`NOTICE` 与 `skin.json` 声明底图由 AI 生成并加贡献者责任句；可读性数字按宿主真正的两层合成重算，皮肤版本 1.1.0
- `model-dorm` 补上浮动层令牌（6e55b02、8fee859，经 #68 合入）：把此前留给加载器推导的 14 条非字体令牌逐个追到消费点，色板覆盖从 104/118 提到 115/118。`--dsw-shadow-lv1/2/3` 与 `--dsw-elevation-stroke-color` 的值就是黑色本身，不再是结构，于是从纯黑 `#000000xx` 换到色板最深的 `#32272b`；三条 `--dsw-elevation-*` 配方保留官方形状（发丝描边加两层模糊投影，位移与模糊半径逐字不动），内层黑色一起染色；补上 `--dsw-linear-gradient-think` 与 `-think-select`（格式为 `linear-gradient(180deg, <页面底色> 20.19%, <同色透明> 100%)`）；`--dsw-mask-blur` 与 `--dsw-menu-backdrop-filter` 按签名有意不动。高程族需要一条 `*` 规则：官方主题在 `body, body *` 上声明它，写在 `:root` 的值传不到后代，CDP 的 `getMatchedStylesForNode` 也确认皮肤写在 body 上的规则 `matchesCard: false`，所以只靠 `!important` 赢不了，规则必须匹配到元素本身。同时声明官方组件 CSS 消费而契约没列的运行时令牌（`--dsw-focus-ring-color`、`--dsw-radius-sm/md/lg`、`--dsw-focus-ring-width` 等），半径阶梯按这套皮肤自己的圆角尺度走。另修正三条写错名字的令牌：`--dsw-alias-menu-surface-fill` → `--dsw-menu-surface-fill`、`--dsw-alias-turn-trigger-hover` → `--dsw-alias-turn-trigger-bg-hover`、删掉重复的 `--dsw-alias-state-warning-primary`（正确名为 `--dsw-alias-state-warn-primary`），并修掉 README 里「21 条漏掉的令牌」与 CSS 注释里「阴影 alpha 照原样保留」两处与事实不符的说明，皮肤版本 0.1.1

### 修复

- 全屏面板与设置对话框改为不透明绘制（4942dc1，#102）：贴上皮肤后，右栏全屏视图与设置对话框都让对话直接透读，因为这两个元素本身没有不透明底：全屏面板是 100vw 覆盖层，内层表面继承皮肤的透明填充（窗格宿主取 `--dsw-alias-bg-base`，62 套目录皮肤里有 50 套把它重映射到约 10%，另有四套给 `[data-dockkit-content]` 加约 34% 的填充），设置对话框的底板是 `--dsw-alias-bg-layer-2`（跨皮肤 42% 到 96% alpha）。现在在共享的 shell-rendering 样式表里用皮肤自己的颜色按满 alpha 画这两块表面，一条规则跟着所有皮肤、皮肤不必声明新令牌；相对颜色语法省略 alpha 时会继承原色 alpha，所以显式写 `/ 1`，前面留一条退回声明给不支持相对颜色的引擎。规则分别挂在 `html[data-dsh-skin]` 与 `html[data-dsh-custom-theme]:not([data-dsh-skin])` 两个活动视觉头下。停靠（push）模式有意不动：旁边那列看得见底图是设计，不是报告里的问题。`tests/shell-rendering.spec.ts` 钉住这两条规则、两个视觉头下的作用域、退回声明与 push 目标不存在
- 全屏面板只在展开时绘制（37fa7f3）：面板常驻挂载，记住全屏模式的会话在收起时也带着 `data-sidebar-right-panel="fullscreen"`，不带限定的话这条规则会在对话背后铺一块视口大的不透明底，对话没画东西的地方就成黑带。规则加上 `[data-sidebar-right-open]`，只在右栏展开时绘制，spec 里也把这条形状钉住
- 附件栏不再参与发送键规则（17c23ea，#100）：发送键靠排除法定位（输入卡内 `button:not([aria-haspopup])`），官方附件栏每张图登记两个同样没有 `aria-haspopup` 的按钮，于是那条规则族把删除键也一起改造了：`position: relative` 把删除键拉回文档流、推出 64px 的 `.imageItem`，`imageItem:hover .remove` 的显示也跟着失效，删除按钮就此消失，发送键的渐变与圆角也落到两个控件上。改用稳定的注册名 `data-slot=conversation.input.attachments` 排除整个 slot 子树，四套共用该规则模板的皮肤（`whale-fantasy`、`rainy-night`、`shuimo-danqing`、`xinghai-heart`）逐条应用；新增 `tests/composer-send-key-attachments.spec.ts` 把排除钉在每套皮肤的每条选择器上，防止复制到新皮肤时悄悄带回来
- equation-sea 可读性修复（367e0a8，#104）：右栏去掉 blur 与重复的 dock 底色，只留一层薄纱；文字令牌改成暖象牙（暗色）与更深的墨色（亮色），对话、右栏与市场卡片里每个文字令牌都在最亮背景像素上过 4.5:1；市场卡片加深填充、描边与投影，粘性表头接近不透明（98%），滚动时卡片不再透字。预览与两份 README 的可读性表按新值重出
